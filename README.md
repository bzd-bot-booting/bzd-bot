# BZD Bot

Telegram-бот для поиска железнодорожных билетов, мониторинга наличия свободных мест и автоматизации бронирования.

Проект разработан на Python с использованием aiogram, Playwright и PostgreSQL. Для развёртывания предусмотрен Docker Compose. Для централизованного сбора и просмотра журналов используются Grafana, Loki и Promtail.

Готовый Docker-образ публикуется в открытом репозитории Docker Hub: [bzhdbot/bzhd-bot](https://hub.docker.com/r/bzhdbot/bzhd-bot).

- Восстановление активных мониторингов после перезапуска приложения.
- Хранение пользователей, мониторингов и задач в PostgreSQL.

## Архитектура

Система состоит из нескольких взаимодействующих компонентов.

| Компонент      | Назначение                                              |
| -------------- | ------------------------------------------------------- |
| Telegram Bot   | Принимает команды и сообщения пользователей             |
| aiogram        | Обрабатывает обновления Telegram Bot API                |
| aiogram-dialog | Реализует диалоговые сценарии                           |
| Playwright     | Автоматизирует взаимодействие с веб-сайтом              |
| PostgreSQL     | Хранит пользователей, мониторинги и задачи бронирования |
| SQLAlchemy     | Обеспечивает взаимодействие с базой данных              |
| Alembic        | Управляет изменениями структуры базы данных             |
| Grafana        | Предоставляет интерфейс просмотра журналов и дашбордов  |
| Loki           | Принимает и хранит журналы                              |
| Promtail       | Передаёт журналы в Loki                                 |

При полном запуске Docker Compose используются пять сервисов:

- `bot` — основное приложение;
- `postgres` — база данных;
- `grafana` — интерфейс мониторинга;
- `loki` — хранилище журналов;
- `promtail` — сбор и передача журналов.

Перед началом обработки запросов приложение загружает конфигурацию, применяет миграции базы данных и проверяет подключение к PostgreSQL.

## Требования

Для развёртывания через Docker Compose:

- Linux-сервер или компьютер с Linux;
- Docker Engine;
- Docker Compose Plugin;
- токен Telegram-бота;
- доступ к интернету.

Для локального запуска без Docker дополнительно необходимы:

- Python 3.13;
- PostgreSQL 16 или совместимая версия;
- установленные зависимости из `requirements.txt`.

Для запуска через Docker Compose локальная сборка образа не требуется. Используется готовый публичный образ:

```
bzhdbot/bzhd-bot:latest
```

## Установка

Клонируйте репозиторий:

```
git clone https://github.com/bzd-bot-booting/bzd-bot.git
cd bzd-bot
```

Создайте локальный файл конфигурации на основе шаблона:

```
cp .env.example .env
```

Откройте его для редактирования:

```
nano .env
```

Заполните обязательные параметры, сохраните файл и закройте редактор.

## Настройка окружения

### Обязательные параметры

| Переменная               | Назначение                                        |
| ------------------------ | ------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`     | Токен Telegram-бота                               |
| `DATABASE_URL`           | Строка подключения к PostgreSQL                   |
| `BOOKING_ENCRYPTION_KEY` | Ключ шифрования данных бронирования               |
| `POSTGRES_PASSWORD`      | Пароль PostgreSQL при полном Docker-развёртывании |
| `GRAFANA_ADMIN_PASSWORD` | Пароль администратора Grafana                     |

При полном запуске через `docker-compose.yml` строка подключения бота к PostgreSQL переопределяется автоматически и использует внутреннее имя сервиса `postgres`.

Для локального запуска и режима `docker-compose.bot-only.yml` необходимо самостоятельно указать корректный `DATABASE_URL`.

### Дополнительные параметры приложения

| Переменная                | Значение по умолчанию | Назначение                                  |
| ------------------------- | --------------------- | ------------------------------------------- |
| `CHECK_INTERVAL`          | `30`                  | Интервал проверки мониторинга в секундах    |
| `MAX_TICKETS_PER_REQUEST` | `9`                   | Максимальное количество билетов в запросе   |
| `PLAYWRIGHT_HEADLESS`     | `true`                | Запуск браузера без графического интерфейса |
| `PAGE_TIMEOUT_MS`         | `90000`               | Тайм-аут операций браузера                  |
| `PAGE_WAIT_MS`            | `2000`                | Дополнительная задержка ожидания страницы   |
| `ADMIN_CHAT_IDS`          | пусто                 | Telegram ID администраторов через запятую   |
| `TRAIN_TIMEZONE`          | `Europe/Vilnius`      | Часовой пояс времени поездов                |

### Параметры электронной почты

Отправка отчётов по электронной почте настраивается через SMTP.

| Переменная                    | Назначение                           |
| ----------------------------- | ------------------------------------ |
| `SMTP_HOST`                   | Адрес SMTP-сервера                   |
| `SMTP_PORT`                   | Порт SMTP-сервера                    |
| `SMTP_USERNAME`               | Имя пользователя SMTP                |
| `SMTP_PASSWORD`               | Пароль или пароль приложения         |
| `SMTP_USE_SSL`                | Использование SSL                    |
| `SMTP_STARTTLS`               | Использование STARTTLS               |
| `SMTP_TIMEOUT_SECONDS`        | Тайм-аут SMTP-соединения             |
| `SMTP_ERROR_COOLDOWN_SECONDS` | Интервал подавления повторных ошибок |
| `EMAIL_FROM`                  | Адрес отправителя                    |
| `EMAIL_TO`                    | Адрес получателя                     |
| `REPORT_TIMEZONE`             | Часовой пояс ежедневных отчётов      |
| `REPORT_HOUR`                 | Час отправки отчёта                  |
| `REPORT_MINUTE`               | Минута отправки отчёта               |

SMTP можно не настраивать, если отправка почтовых отчётов не требуется.

## Генерация ключа шифрования

Для шифрования чувствительных данных используется Fernet из библиотеки `cryptography`.

Сгенерируйте ключ:

```
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Скопируйте полученное значение в `.env`:

```
BOOKING_ENCRYPTION_KEY=СГЕНЕРИРОВАННЫЙ_КЛЮЧ
```

**Важно:** после сохранения зашифрованных данных в базе нельзя произвольно менять ключ. Без исходного ключа ранее сохранённые данные не удастся расшифровать. Обязательно сохраните резервную копию ключа в надёжном месте.

## Запуск через Docker Compose

Основной способ развёртывания — запуск полного набора сервисов через Docker Compose с использованием готового образа из Docker Hub.

Репозиторий образа:

- Docker Hub: [https://hub.docker.com/r/bzhdbot/bzhd-bot](https://hub.docker.com/r/bzhdbot/bzhd-bot)
- Имя образа: `bzhdbot/bzhd-bot:latest`

Для обычного развёртывания локальная сборка из исходного кода не требуется.

Проверьте наличие Docker:

```
docker --version
docker compose version
```

После заполнения `.env` проверьте конфигурацию:

```
sudo docker compose config -q
```

Загрузите актуальные образы:

```
sudo docker compose pull
```

Запустите сервисы:

```
sudo docker compose up -d
```

Проверьте состояние контейнеров:

```
sudo docker compose ps
```

Просмотрите журналы бота:

```
sudo docker compose logs -f bot
```

Просмотрите журналы всех сервисов:

```
sudo docker compose logs -f
```

При запуске приложения миграции Alembic применяются автоматически.

### Доступ к Grafana

При стандартной конфигурации интерфейс Grafana доступен локально:

```
http://localhost:3000
```

Учётные данные задаются через переменные:

```
GRAFANA_ADMIN_USER=admin
GRAFANA_ADMIN_PASSWORD=ВАШ_ПАРОЛЬ
```

Loki в стандартной конфигурации доступен локально:

```
http://localhost:3100
```

Порты Grafana и Loki привязаны к `127.0.0.1`, поэтому сервисы не публикуются на всех сетевых интерфейсах хоста.

## Запуск только бота

Файл `docker-compose.bot-only.yml` предназначен для серверов, на которых PostgreSQL и инфраструктура мониторинга уже развёрнуты отдельно.

В `.env` необходимо указать адрес доступной базы данных:

```
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST:5432/DATABASE
```

Загрузите образ бота:

```
sudo docker compose -f docker-compose.bot-only.yml pull
```

Запустите контейнер:

```
sudo docker compose -f docker-compose.bot-only.yml up -d
```

Проверка состояния:

```
sudo docker compose -f docker-compose.bot-only.yml ps
```

Просмотр журналов:

```
sudo docker compose -f docker-compose.bot-only.yml logs -f bot
```

## Локальный запуск

Создайте виртуальное окружение:

```
python3 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```
pip install -r requirements.txt
```

Установите браузер Chromium для Playwright:

```
playwright install chromium
```

Убедитесь, что PostgreSQL запущен, а `DATABASE_URL` указывает на доступную базу данных.

После настройки `.env` запустите приложение:

```
python main.py
```

Для остановки используйте сочетание клавиш `Ctrl+C`.

## База данных и миграции

Для управления структурой PostgreSQL используется Alembic.

При стандартном запуске приложения миграции автоматически применяются перед началом работы бота.

При необходимости миграции можно запустить вручную.

В контейнере:

```
sudo docker compose exec bot python -m alembic upgrade head
```

Просмотр текущей версии:

```
sudo docker compose exec bot python -m alembic current
```

Просмотр истории миграций:

```
sudo docker compose exec bot python -m alembic history
```

Данные PostgreSQL при полном Docker-развёртывании хранятся в именованном томе `postgres_data`.

Не удаляйте этот том без необходимости: в нём находятся данные приложения.

## Мониторинг и журналы

Инфраструктура мониторинга включает три основных компонента:

- **Grafana** — интерфейс просмотра дашбордов;
- **Loki** — хранилище журналов;
- **Promtail** — сбор и передача журналов в Loki.

Конфигурации компонентов находятся в каталоге `deploy/`.

Перезапуск Grafana:

```
sudo docker compose restart grafana
```

Просмотр журналов Grafana:

```
sudo docker compose logs --tail=100 grafana
```

Просмотр журналов Loki:

```
sudo docker compose logs --tail=100 loki
```

Просмотр журналов Promtail:

```
sudo docker compose logs --tail=100 promtail
```

В проекте также предусмотрен вспомогательный скрипт:

```
./start_grafana.sh
```

Он проверяет наличие Docker и Docker Compose, проверяет конфигурацию и запускает сервис Grafana.

## Полезные команды

Загрузка актуальных образов:

```
sudo docker compose pull
```

Запуск всех сервисов:

```
sudo docker compose up -d
```

Обновление только бота:

```
sudo docker compose pull bot
sudo docker compose up -d bot
```

Остановка сервисов:

```
sudo docker compose stop
```

Запуск остановленных сервисов:

```
sudo docker compose start
```

Остановка и удаление контейнеров и сети:

```
sudo docker compose down
```

Проверка состояния:

```
sudo docker compose ps
```

Просмотр последних журналов бота:

```
sudo docker compose logs --tail=100 bot
```

Команда `docker compose down` не удаляет именованные тома. Не добавляйте параметр `-v`, если не планируете удалить данные PostgreSQL и Grafana.

## Безопасность

- Не добавляйте `.env` в Git.
- Не публикуйте Telegram Bot Token.
- Не публикуйте пароли PostgreSQL и SMTP.
- Не публикуйте `BOOKING_ENCRYPTION_KEY`.
- Не храните реальные пользовательские данные в репозитории.
- Не добавляйте журналы и runtime-файлы в Git.
- Используйте уникальные пароли для PostgreSQL и Grafana.
- Ограничивайте доступ к административным интерфейсам.
- Регулярно создавайте резервные копии базы данных.
- Сохраняйте ключ шифрования в надёжном месте.

Файл `.env.example` содержит только шаблонные значения. Перед запуском необходимо заменить их собственными параметрами.
